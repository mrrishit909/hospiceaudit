HospiceAudit checks synthetic hospice episode records against HA-DEMO-1, a fictional four-rule documentation contract. Each finding cites the episode, document or requirement behind it. A human reviewer records the decision.

How a review runs in the workbench

  1. i

    Load

    Choose a bundled synthetic fixture. Validation is atomic: the whole input is accepted, or a list of coded errors comes back and nothing is processed.

  2. ii

    Inspect

    Read the episodes, documents and requirements as tables before any rule runs.

  3. iii

    Run HA-DEMO-1

    Get a frozen, deterministic report with a chronology strip per episode. The same input gives byte-identical output.

  4. iv

    Review

    Open a finding to see its cited records and rule pack provenance. Set a decision and add a note.

  5. v

    Export

    Download JSON or CSV. Every export carries its data-origin label and the review layer, kept apart from the frozen findings.

The four fictional rules

HA-DEMO-1 is a demonstration contract written for this project. It is not derived from any regulation.

HA01 Required document missing
A required episode and kind pair has no document at all.
HA02 Document unsigned
A document exists but its signature date is empty.
HA03 Document signed after billing date
A signature falls on a later calendar day than the episode's billing date. Signing on the billing date itself is not a finding.
HA04 Billing date before episode start
The episode's billing date is an earlier calendar day than its start date.

The reviewer decides, not the engine

Each finding has one decision from a fixed list. It stays open until a person changes it. A note of up to 2,000 characters can sit beside it. Decisions and notes are stored outside the frozen report, so reviewing never alters the findings.

  • open
  • confirmed
  • dismissed
  • escalated

Notes and decisions live only in the open page until you export them. The workbench does not save them.

What it does not do

  • It makes no clinical, financial, eligibility, entitlement or compliance determination, and shows no monetary figures.
  • It does not interpret Medicare, CMS or any regulator's policy. HA-DEMO-1 is fictional.
  • It does not detect or block real patient data. A local JSON file you open in the workbench is read in your browser, never sent anywhere, and labelled UNVERIFIED USER-SUPPLIED DATA. That label is a disclosure, not a control. Do not use real records.
  • It is not production software. A qualified hospice compliance expert would have to review any authoritative rule pack, and privacy, security and legal approval must come before any real data.
  • Its tests are the implementer's own checks, not an independent audit.
